# 爱奇艺广告跳过（Edge / Chrome 扩展）

在爱奇艺网页版跳过前贴片与中插广告。**不拦截任何请求，不改动视频流**，因此不会触发平台的"广告被拦截"提示，播放器也不会卡死。

实测（2026-10-15，爱奇艺体育点播页）：

| 指标 | 未装扩展 | 装上扩展 |
|---|---|---|
| 广告素材请求数 | 3 | **0** |
| 前贴片广告时长 | 61 秒 | **0 秒** |
| 反拦截遮罩 | 无 | 无 |
| 站内切集后 | 又一轮广告 | **仍然 0** |

---

## 原理

广告不在视频流里。播放器的内嵌 SDK（`@iqiyi-ad-fe/cupid-mars`）会发一个 JSONP 请求：

```
GET https://t7z.cupid.iqiyi.com/mixer?...&cb=Q<32位hex>
→ Q1a2b3c...({ ... "adSlots":[{ "duration":61, "ads":[3支广告] }] ... })
```

JSONP 的执行顺序是「**注册回调 `window[cb]` → 插入 `<script>` → 响应到达 → 调用回调**」。
`<script>` 从插入 DOM 到真正执行之间必然隔着一次网络往返（宏任务），而 `MutationObserver` 回调是微任务——**我们总能在回调拿到数据之前，把它包一层**。

包装后的回调会先把 `adSlots[].ads` 清空、`duration` 归零，再交给播放器自己的处理函数。于是请求照常成功、检测器认为一切正常、播放器认为"本集无广告"。

**为什么不用更简单的做法：**

| 做法 | 结果 |
|---|---|
| 拦掉 mixer 请求 | 触发平台反拦截检测，白等约 40 秒才放正片 |
| 拦广告素材 `/videos/other/` | 播放器卡死，反复重试 |
| 扩展直接重定向/改响应体 | MV3 的 `declarativeNetRequest` 改不了响应体；静态重定向会让动态 `cb` 回调名失配 |
| 本方案：包装 JSONP 回调 | **零等待，无遮罩，无副作用** |

## 安装（Edge）

1. 打开 `edge://extensions/`
2. 打开左下角 **"开发人员模式"**
3. 点 **"加载解压缩的扩展"**，选择本目录（`iqiyi-ad-skip`）
4. 打开爱奇艺任意视频页即可

Chrome 同理：`chrome://extensions/` → 开发者模式 → 加载已解压的扩展程序。

> 装好后可以打开 DevTools 控制台，正常工作时会打印 `[ad-skip] 已中和 1 处广告数据`。

## 已验证范围

- ✅ 爱奇艺体育（`sports.iqiyi.com`）点播页：前贴片（`cuepointType:1`）
- ✅ 同一页面内点击侧边栏切换集数（SPA 站内导航，会重新请求 mixer）
- ✅ 无头 Edge + 真实 Edge 均通过

## 未验证 / 已知边界

- ⚠️ **直播页**走的是另一套链路（代码里有 `/liveshow/` → `/liveugc/` 的 URL 改写），未测试。
- ⚠️ **中插广告**（`midrollPoints`）代码里已清空，但测试样本中该字段本来就是空的，没有实际样本可验证。
- ⚠️ **主站 `www.iqiyi.com`** 用的是 `/show2` 接口（本扩展只匹配 `/mixer`），未测试，因此**不会**影响主站播放；如果哪天主站也要支持，需要单独验证响应结构再放宽匹配。
- 服务端会滚动下发配置（响应里的 `version` 字段），字段名一旦变更，需要同步改 `inject.js` 里的 `neutralize()`。

## 兼容性

- Edge / Chrome 111+（依赖 manifest 的 `world: "MAIN"` 内容脚本能力）
- 只注入 `*.iqiyi.com`，不触碰其他站点；无后台常驻、无网络请求、不读取任何用户数据

## 卸载

`edge://extensions/` 里关掉开关或直接移除。

---

## 提醒

跳过广告违反《爱奇艺用户服务协议》，平台有权对账号作处理。本扩展只作用于你本机浏览器内的页面数据，不修改请求、不涉及账号凭证，风险远低于任何"魔改客户端 / VIP 解析站"。介意的话，开会员仍是唯一不破坏协议的做法。
